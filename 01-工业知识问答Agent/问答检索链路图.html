事件载荷说明
start{request_id, steps}连接即发；steps = MAIN_PROGRESS_NODES 预渲染清单（意图理解/检索规划/知识图谱检索/RAG 检索/证据融合/补检判定/推理回答/置信评估），故意不含 direct——否则直答时会常驻一个永不完成的步骤
step{node, status, label, seq, elapsed_ms?}主链节点进度，on_progress 透传；补检节点触发时才动态出现
token{text}答案裸增量；固定文案类（零证据短路、direct 直答）一次性推一帧，前端不白屏；仅检索模式是 8003 把拼好的正文按行当 token 推（伪流式，行间 30ms）
done与 /api/chat 同构的完整信封code/msg/answer/route/sources/iterations/confidence/warnings/request_id/…/files?；answer 已 normalize_range_tildes 定稿
error{code, msg, request_id}HTTP 仍 200，沿用 chat_adapter 错误码；传输层错误码 50302

五条必须知道的坑

  • 前端以 done.answer 覆盖流式拼接结果：服务端做过区间波浪线归一（20~50V → 20–50V）、表格/文档还前置了附件导语，覆盖即自愈，所以流式与一次性两条路径的最终展示必然一致。
  • 五种模式全覆盖，前端不留分支：rag / agent / 带附图 / excel / doc 都是真流式（agent 侧 /api/chat/stream 一路透传）；仅检索因为这条通道压根没有大模型生成（正文由 8003 的 _compose_retrieve_answer 拼装），由 8003 自产 start → step(检索中/检索完，带 elapsed_ms) → token×N（按行，splitlines(keepends=True) 保证拼接与 done 逐字相同）→ done 补齐合同。
  • 8003 只在 done 帧到达才落 assistant：未见 done 就断流 → assistant 以 failed=True 落库（正文 = 已收 token 前缀 + 失败原因），衔接既有 retry 端点原位重试。finally 里保证落库判定恰好一次，且 finally 内不能 yield。
  • reason/conf 的 step 帧在 token 之后才到 ⇒ onStep 里必须 if (buf) return，否则正文已经长出来了、阶段文案还在往上盖。
  • FastAPI ≥0.106 在响应体开始流式输出之前就退出 Depends(get_db) ⇒ 流式体内必须新开 SessionLocal()；客户端断开是 CancelledError（BaseException），落库逻辑必须放 finally。

退化路径只剩一种：装配层没注入 run_query_stream_fn（LLM 未配置也走这里）时，agent 侧直接调 chat() 再包成 start + done 两帧——合同统一，前端不用分支处理。带附图不再退化：图只是给模型多一份上下文（以图搜图 + 图文互证），image 一路透传进流式主链，检索阶段的进度由 step 帧承担，正文照样逐 token 推。

九、容易误解的点（实测核实）

  1. 多轮记忆在 agent 侧（Mongo sessions），qa-backend 只传 conversation_id；qa-backend 自己的会话/消息存 SQLite。
  2. BM25 稀疏路已开——不再是 dense 单路；两路分别查 + 应用层 RRF k=60 等权。sources[].kind 会出现 "bm25"。
  3. 不是「一次检索就生成」：fusion 判充分性，不够最多补检 3 轮（前端「补检 N 轮」即此）。
  4. 图谱检索不限定 ACTIVE 状态：前端不选图谱 = 跨全部已发布图谱查 Neo4j。
  5. 实体名解析只改「喂进去的名字」，Cypher 逐字未动。
  6. 零证据不调 LLM：直接短路返回「现有知识库证据不足」；但非知识类问题现在压根到不了这一步。
  7. 意图不是四分类也不是 13 类：13 个专业标签 + 5 档非知识类，两层闸分流。
  8. 流式与一次性共用同一个信封：done 帧 = /api/chat 的完整响应，前端以 done.answer 覆盖拼接结果。现在新提问已经全部走流式（带图 / excel / doc / 仅检索都在内，仅检索是 8003 侧伪流式），一次性只剩失败重试；所以"token 拼接 ≠ done 正文"的两处差异（波浪线归一、附件导语）全靠这次覆盖抹平，不是 bug。
  9. 带图不是"一次性"的理由早就没了：以前带图被踢出流式，真实原因只是 run_query_stream_fn 的签名里没有 image 参数（不是"产物是整块结构"）。补上这个参数后带图照常逐字推，图片证据 / 缩略图挂 done.sources。
  10. route 有六个值（见第二节末）。
  11. 超时链：kwp 首帧 150s（无整体超时）→ qa-backend 120/180s → agent 200s。
  12. 流式并发闸 = 3 条流（_ask_semaphore 包住整条流，不是包住一次请求）。
  13. 仅检索虽然"没回答"，但不是只在右栏列证据：8003 会把命中片段拼成一段正文（_compose_retrieve_answer，含"未生成回答"的说明），所以它照样有 answer、照样落库、照样进搜索——也正因为有正文可推，才用伪流式让它跟别的模式长得一样。
