## 一、背景与我的范围

基座是一个开源的量化交易平台（多市场行情、策略回测、筛选引擎、实盘对接）。在它之上，我独立设计并实现了
**「简投·智顾」投顾模块** —— 面向基金投资者（ETF + 主动基金）的对话式投顾产品。

**诚实说明**：底层平台不是我从零写的。我做的是**在其之上做二次开发**，投顾模块的每一个接口、每一个页面都是我实现的。
这种"基于成熟基座做垂直模块"的方式在工程上很常见 —— 不需要重造行情接入和账户体系，把力气花在业务上。

## 二、投顾模块：13 个接口

| 接口 | 能力 |
|---|---|
| `sentiment` | **市场情绪指数** —— 20+ ETF 涨跌分布、情绪指数与趋势 |
| `themes` | **主题趋势评分** —— 按主题聚合 ETF，打分 0-100，输出强势/中性/弱势 |
| `valuation` | **ETF 估值分位** —— 指数 PE 的历史百分位，判断高估/低估 |
| `allweather` | **全天候轮动** —— 波动率调节的资产配置 |
| `dividend` | **股息 / 现金流策略** —— 高股息 ETF、REITs、红利基金对比 |
| `screen` | **基金筛选** —— 多条件筛选 |
| `benchmark` | 基准对比 |
| `compare` | 组合情景对比 |
| `trend30` | 30 日表现趋势 |
| `kline` | ETF K 线预览 |
| `monthly` | 月度持仓检查 |
| `dca` | 定投计算器 |
| `chat` | **AI 对话式投顾** |

### 主题趋势评分怎么算

把 ETF 池按主题分类，取每个主题下的成分 ETF 实时行情，算平均涨跌幅后映射成 0-100 分：

```
score = clamp(50 + 平均涨跌幅 × 5, 0, 100)
```

- `> 60` → 强势 ｜ `< 40` → 弱势 ｜ 其余 → 中性

这是个刻意做的**简单可解释**的评分 —— 投顾场景里，用户看到"为什么是强势"比看到一个黑箱分数重要。

## 三、AI 对话式投顾（模块里最核心的一个）

设计目标是：**用户用自然语言问基金问题，回答要基于当前真实行情，而不是模型的记忆。**

### 上下文组装

每次提问时实时拉取并组装市场上下文：

| 数据 | 来源 |
|---|---|
| ETF 实时涨跌 | 腾讯行情 |
| 30 日收益 | 前复权日 K 线计算 |
| 指数 PE 分位 | 中证指数估值数据（akshare） |

组装成结构化表格注入 system prompt，并给每只标的打**语义标签**：
`🔥强势` / `❄️弱势` / `💎低估` / `⚠️高估` / `适中` —— 让模型不用自己从数字里推断情绪。

### 多轮记忆

按用户维度维护**滑动窗口**的对话历史（保留最近 4 轮），拼进 messages ——
既保证"它刚才说的那个"能被追问，又不会让上下文无限膨胀。

### 降级设计

```
主路径：大模型直连，纯文本输出
   ↓ 失败
兜底：走结构化调用（JSON 输出 + 默认结构）
   ↓ 仍失败
兜底：返回可读的提示文案
```

**三级降级**保证对话功能不会因为某个依赖挂了就直接 500。

## 四、因子有效性评估

单独实现了一套因子评估脚本，用**日频横截面分析**判断筛选因子的预测能力：

- **IC / Rank IC** —— 每个交易日，当日因子值与下一期收益做 Spearman 相关
- 剔除样本量不足的交易日（`n < 30`），避免小样本噪音污染统计量

用于回答一个具体问题：**筛选器用的因子，到底有没有预测能力，还是只是看着合理。**
